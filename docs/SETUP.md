# Kafka SSL Lab v8 — Setup Guide

## Overview

3-broker Apache Kafka cluster using `confluentinc/cp-kafka:8.2.0` (Apache Kafka 4.2) in KRaft mode (no ZooKeeper), with a layered security stack:

| Layer | Technology |
|-------|-----------|
| Transport encryption | TLS with mutual certificate authentication |
| Authentication (password) | SASL SCRAM-SHA-256 |
| Authentication (Kerberos) | SASL GSSAPI via MIT Kerberos 5 |
| PKI | Self-signed CA, per-broker and per-client certificates |
| Key format | PKCS12 keystores (Confluent Docker native format) |

**Host:** AlmaLinux, IP `<KAFKA_HOST_IP>` | **Memory:** ~2.5 GB total (KDC: 256 MB, each broker: 768 MB)

## Architecture

```
Host: <KAFKA_HOST_IP> (AlmaLinux)
  │
  ├── :9093 ──► kafka1 (172.30.0.11)  [SASL_SSL — broker + controller]
  ├── :9094 ──► kafka2 (172.30.0.12)  [SASL_SSL — broker]
  └── :9095 ──► kafka3 (172.30.0.13)  [SASL_SSL — broker]

Docker network: kafka-sasl-ssl-lab_kafka-net  172.31.0.0/24
  ├── 172.30.0.10   kafka-kdc
  ├── 172.30.0.11   kafka1   (broker + KRaft controller)
  ├── 172.30.0.12   kafka2   (broker)
  └── 172.30.0.13   kafka3   (broker)
```

### Listener Map

| Listener | Protocol | Port | Accessible from | Purpose |
|----------|----------|------|-----------------|---------|
| `SASL_SSL` | SASL_SSL | 9093–9095 | Host + external | Client connections |
| `INTERNAL` | PLAINTEXT | 19093–19095 | Docker network only | Inter-broker replication |
| `CONTROLLER` | PLAINTEXT | 9096 | Docker network only | KRaft quorum (kafka1 only) |

**Why PLAINTEXT for CONTROLLER and INTERNAL?** SCRAM credentials are stored in Kafka's own metadata log. At first boot the log is empty — SCRAM authentication cannot succeed, so the cluster can never start. These listeners are only reachable inside the Docker network so PLAINTEXT is acceptable.

### KRaft Mode

kafka1 is both broker and KRaft controller. kafka2 and kafka3 are brokers only. ZooKeeper was removed in CP 8.0 — KRaft is the only supported mode.

```
KAFKA_PROCESS_ROLES: broker,controller   # kafka1
KAFKA_PROCESS_ROLES: broker              # kafka2, kafka3
KAFKA_CONTROLLER_QUORUM_VOTERS: "1@kafka1:9096"
CLUSTER_ID: "ErAddTzdTLSPKOogQn1N3w"
```

## Security Stack

### SSL / TLS

- 2048-bit RSA keys, 10-year validity, self-signed CA
- Broker certs include SAN: `DNS:kafkaX`, `IP:<KAFKA_HOST_IP>`, `IP:127.0.0.1`
- Mutual TLS enabled: `KAFKA_SSL_CLIENT_AUTH: required`
- All files mode `644` — required because brokers run as `appuser` (uid=1000)

### SASL Mechanisms

Two mechanisms on the `SASL_SSL` listener:

```yaml
KAFKA_SASL_ENABLED_MECHANISMS: SCRAM-SHA-256,GSSAPI
```

**SCRAM-SHA-256** — username/password stored in Kafka's metadata log. Created after cluster starts via `create-scram-users.sh`.

> **CP 8.x note:** The default SCRAM mechanism changed to SHA-512 in CP 8.0. This lab explicitly sets `SCRAM-SHA-256` in `KAFKA_SASL_ENABLED_MECHANISMS` and all JAAS configs to maintain SHA-256 — no client-side config changes required.

**GSSAPI (Kerberos)** — each broker authenticates with its own keytab. Clients authenticate with `kafkaclient.keytab`.

### JAAS Configuration

Per-listener JAAS is set via environment variables in `docker-compose.yml` and takes precedence over the global JAAS file:

```
KAFKA_LISTENER_NAME_SASL__SSL_SCRAM_SHA_256_SASL_JAAS_CONFIG
KAFKA_LISTENER_NAME_SASL__SSL_GSSAPI_SASL_JAAS_CONFIG
```

`certs/broker/kafka_jaas.conf` is a stub generated by `generate-certs.sh`. It exists only to satisfy the Confluent Docker startup check (`KAFKA_OPTS` must point to an existing JAAS file when GSSAPI is enabled). It has no effect on actual authentication.

**JAAS values must be single-line strings.** YAML `|` block scalars embed literal newlines which Kafka's JAAS parser rejects with "entry not terminated by semi-colon".

## Setup Procedure

### Recommended — Quick Start

```bash
cd kafka-sasl-ssl-lab
chmod +x quick-start.sh scripts/*.sh
./quick-start.sh
```

`quick-start.sh` runs all 6 steps in order and handles all waits automatically. On first run it pulls `cp-kafka:8.2.0` (~1.3 GB) and builds the KDC image.

### Manual Step-by-Step

#### Step 1 — Generate SSL Certificates

```bash
bash scripts/generate-certs.sh
```

Creates all files under `certs/`: CA, broker certs, client cert, PKCS12 keystores, credential files, and `kafka_jaas.conf` stub. All files set to mode `644`.

#### Step 2 — Start Containers

```bash
docker compose up -d
```

Starts `kafka-kdc`, `kafka1`, `kafka2`, `kafka3`. The KDC image (`kafka-sasl-ssl-lab-kdc`) is built from `kerberos/Dockerfile` on first run.

#### Step 3 — Setup Kerberos

```bash
sleep 10
bash scripts/setup-kerberos.sh
```

- Fixes `kdc.conf` (RHEL default points to `EXAMPLE.COM`, not `KAFKA.LOCAL`)
- Rebuilds KDC database with a known master key to avoid encryption type mismatches
- Creates 4 principals and exports keytabs with mode `644`
- Auto-copies `kafkaclient.keytab` to `certs/keytabs/`

> **Known fix in v8:** `setup-kerberos.sh` uses `docker compose restart kdc` (service name) not `kafka-kdc` (container name). Using the container name causes "no such service" and the script exits prematurely.

> Always delete old keytab files before re-running if the KDC database was reset — `ktadd` appends rather than replaces, and stale entries cause `Checksum failed`.

#### Step 4 — Restart Brokers

```bash
docker compose restart kafka1 kafka2 kafka3
sleep 20
```

Brokers read keytabs at startup. The `keytabs` volume was empty when they first started; they must restart to load the new files.

#### Step 5 — Create SCRAM Users

```bash
bash scripts/create-scram-users.sh
```

Connects via the INTERNAL (PLAINTEXT) listener and stores SCRAM-SHA-256 credentials for `admin`, `app-client`, and `demo-user` in Kafka's metadata log.

#### Step 6 — Create Topics

```bash
bash scripts/create-topics.sh
```

Creates all lab topics and pre-creates `__transaction_state` (required for transactional CDC producers — see [`CDC-CLIENT.md`](CDC-CLIENT.md)).

## Operational Playbook

### Normal Start (volumes intact)

```bash
cd kafka-sasl-ssl-lab
docker compose up -d
# Wait ~30 seconds
docker compose ps
```

SCRAM users and topics persist in the Kafka metadata log volume (`kafka-sasl-ssl-lab_kafka1-data`).

### Full Reset (clean slate)

```bash
docker compose down -v
./quick-start.sh
```

> `docker compose down -v` wipes ALL named volumes. Always run the full `quick-start.sh` after a full reset.

### Regenerate Certificates Only

```bash
docker compose stop kafka1 kafka2 kafka3
bash scripts/generate-certs.sh
docker compose up -d kafka1 kafka2 kafka3
# Push new certs to CDC client host
scp certs/ca/ca-cert.crt certs/client/client.crt certs/client/client.key \
  root@<CDC_CLIENT_HOST_IP>:/opt/cdc-client/certs/
```

> Use `up -d` (not `restart`) after cert changes — Docker bind-mounts track inodes and `restart` may serve the old file.

### Check Cluster Health

```bash
docker compose ps
docker logs kafka1 --tail 50
docker exec kafka1 kafka-broker-api-versions \
  --bootstrap-server kafka1:19093 \
  --command-config /etc/kafka/client-internal.properties
docker exec kafka-kdc kadmin.local -q "listprincs"
```
