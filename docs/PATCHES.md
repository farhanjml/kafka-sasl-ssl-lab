## PATCH-SR-005 — Kafka Connect OOM on startup

**Date:** 2026-06-03  
**Symptom:** `kafka-connect` container crash-loops every ~35s, exit code 0, no error in logs. Port 8083 never opens.  
**Root cause:** Confluent Docker reads `KAFKA_HEAP_OPTS` env var for actual JVM args. `CONNECT_HEAP_OPTS` only writes to the properties file but does NOT set JVM args. Without `KAFKA_HEAP_OPTS`, JVM defaults to `-Xmx2G`, immediately OOM-killed against `mem_limit: 384m` container limit.  
**Fix:** Added `KAFKA_HEAP_OPTS: "-Xms256m -Xmx512m"` to compose env and raised `mem_limit` to `768m`.  
**Files changed:** `docker-compose.yml` — kafka-connect service

## PATCH-SR-004 — Internal services using wrong broker ports

**Date:** 2026-06-03  
**Symptom:** Schema Registry and ksqlDB log `Connection to node X (kafkaX/172.31.0.1X:919X) could not be established` in loop.  
**Root cause:** SR/ksqlDB bootstrapped via SASL_SSL (container port 9093). Broker metadata response advertised `kafkaX:919X` (host-mapped port). From inside Docker, port 919X doesn't exist — broker listens on 909X. Classic Docker port-mapping mismatch for internal services.  
**Fix:** Switched SR/ksqlDB/Connect to INTERNAL listener (`PLAINTEXT://kafkaX:1909X`). Internal Docker network can reach container port 1909X directly without host mapping.  
**Files changed:** `docker-compose.yml` — schema-registry, ksqldb, kafka-connect services

## PATCH-SR-003 — Wrong SCRAM password for app-client

**Date:** 2026-06-03  
**Symptom:** `SASL authentication error: Authentication failed during authentication due to invalid credentials with SASL mechanism SCRAM-SHA-256`  
**Root cause:** `create-scram-users.sh` created `app-client` with password `<APP_SCRAM_PASSWORD>` but the CDC client was configured with a mismatched password.  
**Fix:** Updated Kafka SCRAM credential: `kafka-configs --add-config "SCRAM-SHA-256=[password=<APP_SCRAM_PASSWORD>],SCRAM-SHA-512=[password=<APP_SCRAM_PASSWORD>]" --entity-name app-client`. Updated `create-scram-users.sh` to use the correct password.  
**Files changed:** `scripts/create-scram-users.sh`

## PATCH-SR-002 — SCRAM-SHA-512 not enabled on brokers

**Date:** 2026-06-03  
**Symptom:** Client bootstrap connects then immediately drops (`TRY_CONNECT → DOWN` in ~3s). RC=129 transaction init timeout.  
**Root cause:** `KAFKA_SASL_ENABLED_MECHANISMS: SCRAM-SHA-256,GSSAPI` — SHA-512 missing. Client configured for SCRAM-SHA-512. SASL negotiation failed → broker closed connection → TxnCoordinator never resolved → 120s timeout → RC=129.  
**Fix:** Added `SCRAM-SHA-512` to `KAFKA_SASL_ENABLED_MECHANISMS` on all 3 brokers + added `KAFKA_LISTENER_NAME_SASL__SSL_SCRAM_SHA_512_SASL_JAAS_CONFIG` + added SHA-512 credentials for all users.  
**Files changed:** `docker-compose.yml` — all 3 broker services; `scripts/create-scram-users.sh`

## PATCH-SR-001 — Advertised listeners use container ports instead of host ports

**Date:** 2026-06-03  
**Symptom:** Client connects to bootstrap (port 9193) but then all subsequent connections fail. RC=129 on all traces.  
**Root cause:** `KAFKA_ADVERTISED_LISTENERS` used container ports (`kafka1:9093`) but Docker only publishes host ports (`9193:9093`). Client bootstrap succeeded at 9193, got metadata saying "broker at port 9093", tried port 9093 (closed externally) → failed.  
**Fix:** Changed all broker `KAFKA_ADVERTISED_LISTENERS` to use host-mapped ports: `SASL_SSL://kafka1:9193`, `kafka2:9194`, `kafka3:9195`. INTERNAL listener unchanged (still `19093/19094/19095` — used inside Docker only).  
**Files changed:** `docker-compose.yml` — all 3 broker services

## PATCH-V8-001 — `docker compose restart` service name fix

**Date:** 2026-04-28
**Symptom:** `setup-kerberos.sh` exits with `no such service: kafka-kdc` at Step 4 (KDC restart).
**Root cause:** `docker compose restart` takes a **service name** (`kdc`), not a container name (`kafka-kdc`). The original script used `$KDC_CONTAINER` which is set to `kafka-kdc` for use with `docker exec` commands. The same variable was passed to `docker compose restart`, which looks up services, not containers.
**Fix:** Changed line 77 of `scripts/setup-kerberos.sh` from `docker compose restart $KDC_CONTAINER` to `docker compose restart kdc`.
**Files changed:**
- `scripts/setup-kerberos.sh` — line 77: hardcoded service name `kdc`
